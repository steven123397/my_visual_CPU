engineering problem

我们解决的不是单点功能

一个系统模拟器真正难的地方，在于每层都要和其它层对齐：CPU 语义、外设时序、Guest 期望和调试证据不能互相脱节。

design method

reference-first + 可观察性

1
先保真值来源InstructionSemantics 和 functional backend 是语义基准，pipeline、JIT 原型都围绕它对齐。
2
再扩系统边界从 ISA 到 CSR/trap，再到 MMU、总线、外设、Guest OS 和真实 workload。
3
最后用证据收口每次扩功能都留下 marker、probe、负向测试或前端可观察面，避免“只在我机器上能跑”。

what makes it hard

系统级 bug 往往跨层出现

例如一次 page fault 可能来自 ISA 译码、CSR 权限、Sv39 walk、TLB flush、外设地址区间或 Guest 初始化顺序。项目采用小步 guardrail，把这类跨层问题拆成可定位的检查点。

✓ trap delegation / mret / sret
✓ Sv39 page walk / page fault
✓ UART / CLINT / PLIC / block storage
→ workload marker / debug snapshot / frontend panel

  • 三级页表 walk、TLB、sfence.vma 和 page fault。
  • AddressSpace → Bus → RAM / MMIO 的统一路径。
  • L1D / shadow cache 当前以观察和 opt-in 为边界。
privileged runtime

  • M / S / U 三级特权模式。
  • trap delegation、mret / sret、CSR 访问控制。
  • timer interrupt 与 external interrupt 都有 guest 证据。

  • register rename、ROB、LSQ 和 OoO execute。
  • 投机、flush、rollback 与 side-effect 边界。
  • 通过 pipeline timeline 和 snapshot 做可视化观察。

verification

验证体系

项目的验证目标是避免“能跑但不可信”。因此测试不是单层的，而是 asm、host、guest、frontend、外部 oracle 多层组合。

Layer 1

指令 / 模块

最小 asm、host unit 和模块 smoke 锁住 ISA、CSR、loader、MMU、设备和 helper 行为。

Layer 2

Guest 回归

kernel_alpha 正向 + 负向基线、interactive_os、xv6 shell 和 Linux probe 证明系统链路。

Layer 3

前端 / 服务

Node debug server、terminal input pump、render state 和 workload manifest 有独立 Node 测试。

Layer 4

外部差分

Spike differential 为高风险架构语义提供外部 oracle，尤其适合 trap 和 Sv39 子集。

honest boundary

边界与后续方向

current boundary

当前不做的事

项目已有 JIT、cache、AI、Linux-facing 方向的原型和证据，但结题时不把它们包装成完整商用能力。

! 不默认启用正式 JIT backend
! 不声称完整 Linux 发行版兼容
! 不开放任意 AI 模型上传
! 不声称 multicore / coherence 已完成

next engineering tasks

下一阶段怎么继续

Linux 发行版平台 继续推进 rootfs / Image / DTB、process / filesystem 和 capability 证据。
AI Accelerator 沿 task spec、profile summary 和 simulated cycles，推进更接近 NPU 的性能模型。

Cache / 多核 在现有 L1D / shadow cache 基础上评估 DMA coherence 和 multicore 前置条件。

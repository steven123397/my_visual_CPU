# 系统软件模拟器一致性与可观察性取证计划

Created: 2026-10-02

## 目标与交付边界

本轮交付是证据报告，不是重构。以“在模拟器上观察和诊断 xv6 的 fork、父子进程内存隔离、exit/wait”为目标场景，回答底层实现是否可信、现有观察能力能否解释该过程，以及哪些边界确实需要调整。结果回传原讨论会话后，再决定后续实现计划。

用户已确认：模拟器保持系统软件主线，不转成 AI 项目；先取证再决定调整。本计划不预设必须重写，不将上一轮的架构建议当成已确认缺陷。

本轮不实现 COW，不故意破坏 xv6，不新增 ISA、设备、OoO 或 JIT 能力，不改公共协议、CI、Wiki 契约，不自动创建 Issue、推送、合并或发布。确需新增小型复现夹具时，仅在取证分支添加测试或独立脚本；不足以取证时报告缺口，不借机实现事件平台或修改产品语义。缺陷修复与能力建设交由后续计划。

取证成功不要求所有实验通过：每项问题都有可复核证据或明确的未验证原因，足以决定下一步即可。不得以检查数量或发现数量为目标。

## 证据规则

所有结论标为：已证实行为、已复现缺陷、能力缺口、待验证假设、环境阻断之一。仅发现可疑代码时不能标为缺陷；没有发现分歧不能宣称全 ISA 正确。

每项证据赋予稳定 E-ID；问题赋予 F-ID，仅在报告中记录执行结果，不向本 Plan 添加进度或复选框。

每次运行记录实际 checkout SHA、脏树补丁/内容哈希、后端及配置、guest ELF/镜像/符号文件的 SHA-256、工具链版本与编译参数、客体 CPU 数量、内存/设备配置、输入、停止条件、步骤与墙钟预算、原始命令、退出码和日志位置。临时探针必须记录源码及构建方式，不能只留下二进制。

比较先限定 ISA/特权规范版本、支持子集、初始状态和事件输入。非标准扩展不混入标准 ISA 一致性结论。对规范允许的差异、未定义程序行为、WARL 字段及比较器排除字段逐项说明；不为消除差异而临时放宽断言或从被测输出生成期望。

functional 是项目内部语义基准，不是不可质疑的外部裁判。独立参考只能覆盖配置一致且可比较的场景；记录真实参考可执行文件及版本。fake/mock runner 证据单列为工具自测。通过、失败、超时、取消、跳过、未运行分别记录。

对外部中断和输入，记录注入规则。不能按相同 step 数比较不同后端；不能把合法的调度差异直接当成错误。必要时先以固定输入的短程序排除异步影响，再单独检查定时器和中断。

## 执行顺序

### U1：固定现场并建立覆盖清单

由用户在独立分支/worktree 接手。可从本计划提交开取证分支；若从更新的 main 开始，携带 Plan 并记录与规划基点的差异。代码变动只使受影响证据失效，不因 main 有新提交反复重开整轮取证。

记录构建工具、RISC-V 工具链、外部参考和现有资产是否可用；从当前 Makefile 核对目标与超时，不假定历史命令仍适用。共享 workload 构建与测试先串行，避免镜像相互覆盖。确认已提交源码与正在执行的二进制一致。

成果：版本/环境清单，Q1–Q6 到代码、现有测试、缺口的映射，历史 CI 可复用范围。U1 是后续共同前置条件，不要求先跑完整回归。

### U2：核查行为一致性与副作用边界

回答 Q1、Q2。追踪取指、语义构造、访存、异常、提交的实际调用路径，说明状态由谁修改；重点检查 bypass/helper/旧入口是否绕过统一规则。DBT/JIT 只登记相关旁路，不扩成全后端验收。

优先复用：

- `myCPU/tests/host/backend_differential_smoke.cpp`
- `myCPU/tests/host/address_space_faults_smoke.cpp`
- `myCPU/tests/host/atomic_semantics_smoke.cpp`
- `myCPU/tests/host/pipeline_commit_trace_smoke.cpp`
- `myCPU/tests/host/pipeline_speculation_contracts_smoke.cpp`
- `myCPU/tests/host/spike_differential_smoke.cpp` 及 `spike_differential/`

最小场景覆盖：正常 load/store；对只读或无权限页写入；异常委托和 sret 返回；修改映射并执行适用的 sfence.vma；受控错误路径上的 store/MMIO 不产生不该发生的副作用。预期必须对应选定规范和实现声明，不要求所有失败访问都完全不改变内部状态。

对同一场景比较规定的提交检查点、GPR、相关 CSR、特权级、受观察内存和设备副作用；时间计数器独立分析。现有测试若仅比较最终状态，明确它不能排除中间过程的短暂错误。真实 Spike 环境可用时运行已有真实差分入口，核对归一化与排除字段；不可用时报告环境阻断，其他取证继续，不批量安装或替换工具链。

成果：一致性矩阵和最小证据；分歧先区分模拟器错误、客体错误、夹具错误、模型差异与规范允许差异。出现首个确定分歧即保存复现，不边修边改变基线。

### U3：检查观察链和时间口径

回答 Q3、Q4、Q6。入口包括 `myCPU/src/debug/`、`myCPU/src/mem/address_space.cpp`、`myCPU/src/mem/bus.cpp`、`myCPU/src/exec/execution_profile.*`、`pipeline_sequence.*`、`arch/core_state.cpp`、`devices/clint.cpp`、平台及前端消费路径。

现有验证入口参考 `myCPU/tests/host/debug_cli_smoke.cpp`、`debug_protocol_command_smoke.cpp`、`execution_profile_smoke.cpp`、`run_debug_cli_probe_test.py`。先核查具体命令与断言，再选相关目标执行。

配对场景：固定输入短程序在无观察、开启观察、同一暂停点重复查询三种情况下运行。比较客体可见结果和已定义统计；涉及 UART 读取、PLIC claim 等有副作用地址时，核查调试查询是否误用正常设备读。检查页表查看是否触发 A/D 更新、TLB 填充或 profile 计数，明确哪些查询本来就是会改变状态的调试命令。用正常执行的独立观察确认，不能仅用被检查的 snapshot 证明自己无副作用。

追踪一次访存从发起到返回/异常的完整链：PC、指令关联、特权级、地址空间、VA、PA、TLB/页表路径、访问结果、提交或推测属性。找出现有记录/导出能力，验证记录窗口、丢失/覆盖信号和暂停/继续后的关联。窗口之外不可恢复应报告能力缺口，不要求本轮新增持久事件系统。

形成时间表：每个计数器的单位、推进点、所有者、后端差异、客体可见性、调试查询影响、能支持的结论。宿主秒数不作客体性能；instret 不等于周期；设备 tick 与 backend step 的关系必须实际追踪。

成果：一份真实事件样例、观察副作用配对结果、时间口径表，以及按记录源/关联/保留/协议/前端分层的缺口。

### U4：普通 xv6 fork 场景与架构边界取证

依赖 U2/U3 中与本场景相关的结果，回答 Q4、Q5。若已有确定的语义缺陷导致场景无法成立，保留失败证据，不用内核绕过或模拟器特判让演示通过。

首先复用 `myCPU/tests/host/xv6_boot_smoke.cpp`、`xv6_shell_smoke.cpp` 和现有 forktest；按需要运行已核查的 `test-host-xv6_boot_smoke`、`test-host-xv6_shell_smoke`，记录实际 backend，不能假定 shell 测试覆盖两个后端。长启动遵循工具链经验，超时保留输出与推进证据，不无上限重试。

若现有用例不足，可在取证分支加入最小 guest 夹具：父进程申请并预先写入少量页面；fork；子进程修改其中一页并校验；退出；父进程 wait 后校验原内容。使用同步或检查点定义观察时刻，不依赖固定 PID、固定函数地址或隐含调度顺序。记录该夹具对 guest 镜像的修改和哈希，不将它冒充未修改的上游 xv6。

至少关联父子进程中的一个相同用户虚拟地址：各自地址空间、PTE/权限、物理页、写入前后内容；附 fork、写入、exit/wait 的事件顺序。现有工具无法给出 PID 或过程关联时，手工结合对应 ELF 符号及 guest 结构取证，清楚区分人工推断和自动观察能力。记录进程退出的资源回收证据，区分用户页与内核长期保留对象，不能简单要求所有全局内存计数归零。

检查 OS 语义归属：硬件事实在哪里产生，PID/fork/页归属由谁解释，前端是否猜测核心语义；区分从 RAM 读取的当前 PTE 与 CPU 实际使用的 TLB 映射，禁止用退出后的页表代替当时状态。对 xv6 版本、符号和布局的依赖应进入适配层候选，先列依赖而不实现插件框架。

成果：普通 fork 端到端案例、可观察性缺口、真实职责/依赖图。COW 只记录未来对页权限、异常、TLB 和 OS 适配的要求，本轮不实现、不故障注入、不测性能收益。

### U5：整理回传并建议下一轮范围

依赖 U1–U4；环境阻断的部分允许以明确缺口结束。独立复查每条重要结论能否从证据重建、是否把未验证当通过、是否混淆 OS 与模拟器职责。复核者可由接手会话按风险选择，不要求自动扩成全仓审查。

每个建议只给出最小调整范围、理由、备选和后续验收依据，不提交产品修复。零缺陷也是有效结果，仍应说明是否具备目标场景所需能力。

## 根据证据决定后续工作

| 结果 | 下一步建议 |

## 完成判据与风险

交付报告与证据可在固定输入和版本下复核；所有问题均有结论或未验证原因；正常与负向路径分别说明；探针/客体夹具可追溯；未改变核心行为以掩盖错误；后续调整仍留待用户判断。取证中不承诺最终通过、不承诺发现缺陷、不以功能数量作为完成条件。

局部依赖缺失只阻断相关实验。若生产代码随其他会话变化，重新检查受影响证据。复杂追踪过慢时先缩小程序、事件类型和窗口，并公开覆盖限制；若需要新增生产级基础设施才能继续，停在该项并回传设计缺口。

本 Plan 不引入新的项目领域术语，不创建 CONCEPTS.md。它是研究做法计划，不是已授权的产品实施契约。开工入口为 U1；本会话仅完成规划，用户另开分支取证。

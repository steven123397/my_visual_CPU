## 发现

### [R1-F01] P2 · 待修 · firstForwardedIp 丢失非字符串输入容错

- **位置**：PR #15 的 `frontend/server/security.mjs:71`。
- **来源**：主会话（置信度 100）。
- **问题**：`const parts = value.split(',');` 去掉原有 `String(value)` 后，null、数字和数组会抛出 TypeError。通过 `clientIpForRequest` 传入 null 转发头也会抛错。PR 描述声称处理 null，但新增测试只覆盖 undefined 和字符串。正常 Node HTTP 字符串头未复现异常，此发现是 helper/请求适配层的容错回归，不宣称已证实远程漏洞。
- **建议**：明确 null 的空值语义并保留其他既有输入的字符串归一化，例如 `String(value ?? '')`，补 null、数字和数组案例；跳过空字段的行为需有测试。函数仍未校验 IP 格式，描述应使用“首个非空字段”，避免宣称首个合法 IP。
- **证据**：新 head 原文 `frontend/server/security.mjs:71 -- const parts = value.split(',');`。从该 head 提取模块后分别调用 `firstForwardedIp(null)`、`firstForwardedIp(42)`、`firstForwardedIp(['1.2.3.4','5.6.7.8'])`，均复现 TypeError；null 请求头经消费者也复现。
